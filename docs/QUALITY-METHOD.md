# 对抗式验收方法（v2.0）

五方评审：**新手**能否按步骤完成？**客户**能否验收？**审计员**能否复算成本？**合规负责人**能否确认权利与安全？**维护者**能否复现代码？

## 红队拒收条件（P0）
- 用“必赚钱/日入/月入”担保收益，或把模拟案例当真实成交。
- 虚构求职履历、好评、客户证据或第三方来源。
- 未经许可复制或发布客户资料，或错误地把关闭模型训练选项当成全面保密保证。
- 虚构 ChatGPT 套餐权益、将 Plus 订阅与 API 额度混为一谈。
- 算式把营收冒充利润、忘记人工审核或退款风险。

## 每个商业化 SOP 的验收字段
客户输入、授权记录、明确包含项、排除项、交付文件、客观验收标准、修改次数、变更确认、证据与失败处理。

## 什么可以宣传？
**A 独立验证**：有经客户许可且可核实的来源和范围。**B 客户确认**：有授权和验收记录但不可对外核实。**C 作者自述**：明确标示“未独立核验”。**D 模拟**：虚构演示，不得用于成交成绩宣传。

## 仍待人工/实测验证
无真实客户交付规模、转化率、客单价分布、履约工时、退款率和地区适用法律分析。浏览器与静态测试只证明网站功能和文档结构，不证明模型输出总是正确，也不能确认全网第一。


## v2.2 硬性拒收规则
- 规模、文件数量、仓库状态必须与实际可检查结果一致，不复用过期验收话术。
- 现金结余与个人劳动后差额必须区分，不能隐藏未成交投入和退款成本。
- 每条公开案例必须按D/C/B/A分级，并审查客户对外披露许可。
- CI必须运行普通订单、100%退款、零订单、越界输入、100%预留等算术边界测试。
- Pages依赖测试门禁，测试失败不得部署新版本。
